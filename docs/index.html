This is not a benchmark. It is a way to find bugs in open-source engines and get them fixed.

Every engine runs the same jobs on the same GitHub runner (16 GB RAM), against the same Iceberg tables in one OneLake REST catalog: load raw CSV files, TPC-H-like and TPC-DS-like (Benchmarks), Iceberg writes and table maintenance (Iceberg support), and one dbt project every 2 hours on Spark, Trino, DuckDB and Polars (Real workload).

When a job fails, runs out of memory or returns a wrong answer, the bug is filed upstream: one issue per bug, with a script that reproduces it on a clean machine. The maintainers write the fix; the bench picks it up from main or the next release, and the result here changes (Bug reports).

The timings are not a ranking, and a slow query is not a bug. Running out of memory is: the free runner has 100 GB of free disk to spill to, so there is no technical reason for an OOM.

The SQL, the workflows and every run's logs are in the repo.
