An engine is two things: how fast it runs, and what it supports.

Loading results…

The view is from storage: the tables live in the lake, and every engine is just a client of them.

Every engine gets the same 16 GB machine. An engine that streams its data does not need more.

The work is done in SQL. SQL is a shared language; a new syntax for every engine is not progress.

Iceberg, because an engine attached to a catalog becomes a real database: tables, transactions, many writers.

The state lives in the catalog, so the engine can be stateless: start, do the work, stop. With AI agents starting engines on demand, that matters.

The best query is the one that does the least work. A good optimizer and good pruning beat brute force.

The surprise: the real limit is the runner's local disk, not CPU or memory.

The object store integration matters as much as the engine itself.

When an engine fails, the bug is filed upstream (see Issues).

Tried, not added
