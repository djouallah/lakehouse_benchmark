An agent has no favourite engine. It uses the one that does the job today, and it can change tomorrow.

So the state lives in the catalog, not in the engine. The engine starts, does the work, and stops (Lakehouse).

The work is done in SQL. An agent writes the same SQL for every engine; a new syntax for every engine is not progress.

The first test is simple: read the files, write the tables. Most engines that were tried failed here, on the object store, not on SQL (Issues).

Every engine gets the same 16 GB machine. When a query fails, the agent must get an error. An engine with no memory limit kills the machine, and there is no error to read.

The best query is the one that does the least work: skip the files the query cannot need (File pruning), then pick a good join order. A good optimizer beats brute force (Query plans).

No engine is the fastest on every test. What an engine supports decides; speed is a bonus (Scorecard).

The surprise: the real limit is the runner's local disk, not CPU or memory.

When an engine fails, the bug is filed upstream, with a script that reproduces it (Issues). That is the best help a user can give. It does not need a pull request: the people who know the code write the fix, often within days (Bug reports).

Engines only get better with real competition. Even if you use one engine, it needs to be challenged. Without that, we would still be using Hadoop.

Tried, not added

  • Apache Doris: reads and writes OneLake Iceberg on 4.1.4.1 (TPC-H 22/22), but can't read the raw CSV files in the lakehouse: its file functions take no abfss:// path. Filed: #68877 (open). Details
  • Firebolt Core: reads data only from s3://, gs:// or file://; rejects OneLake's abfss:// paths. Filed: #90 (open).
  • DataFusion Comet: its native Iceberg scan has no abfss://, so OneLake scans fall back to the JVM. Filed: #6058 (open). Details
  • DataFusion: its Python package has no Iceberg support: no catalog, no scan, no write (#1097). The Iceberg table provider, apache/datafusion-iceberg, reads and writes, but it is Rust only and has no release yet. Details
  • pg_lake: (tested on 3.5.3) runs TPC-H 22/22, but has no catalog cache for read-only tables; every statement reloads the metadata, so the 25-row nation takes 4–5s.
