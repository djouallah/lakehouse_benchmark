Engines tried, not added

  • Apache Doris: reads OneLake only with a client secret; with a workload-identity or SAS token the backend crashes.
  • Firebolt Core: reads data only from s3://, gs:// or file://; rejects OneLake's abfss:// paths (#90).
  • Databend: the release build has no Azure storage for Iceberg ("azdls not supported now"); a fix is being tested on a fork (PR #20590, decimal bug #20588).
  • DataFusion Comet: its native Iceberg scan has no abfss://, so OneLake scans fall back to the JVM (#6058).
  • pg_lake (3.5.3): runs TPC-H 22/22, but has no catalog cache for read-only tables; every statement reloads the metadata, so the 25-row nation takes 4–5s.
  • CedarDB: no Iceberg support yet; it's on their roadmap.
  • Daft: ETL only; 16/22 TPC-H queries, the rest fail on decimal precision, cross join and SUBSTRING (#7532, OneLake paths PR #7533).
  • StarRocks: no TPC-DS result; Q49, Q70 and Q86 fail on SQL bugs (#79806, #79807).
  • chDB: not in TPC-DS; aborts on the first query (chDB 4.4.0).
